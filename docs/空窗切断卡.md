# 空窗切断卡（封档）

本卡依据本问“空窗切断只能走空窗误放切断专区中的一种，甲乙不得混用；择定后写入本卡并封档，空窗当天不许改口”的要求，
于实施前一次性择定并封档。后续实现不得偏离本卡；偏离即拦下并记“空窗偏了”。

## 缺陷口径

- 指针（摄入水位 `watermark_clock`）被抬过，却没有对应的到达落行业（`arrivals` 行），形成空窗。
- 空窗期间不得误报绿灯：`/api/catchup/{source}` 在该源存在空窗时一律拦下，不得恢复“可写”。

## 择定路径：甲路径（同库捆提交）

甲路径：把指针推进与到达落行捆成同库提交，遇空（对齐失败/缺到达行）则整段撤销并记空窗审计；
正式水位零推进。不采用乙路径（影子卷预落、对齐失败作废影子），全仓不得出现影子卷机制，甲乙不混用。

## 沿用的既有入口（勿新开空窗台）

- 复用“时限台水位入口”：既有写路径 `POST /api/arrivals`（SLA 时限台）即唯一的指针推进入口。
- 指针推进只能随到达登记在同一事务内发生；不新增独立的“空窗台/水位台”接口。
- 口令沿用本仓空窗侧既有术语：源名录 `sources`、到达 `arrivals`、补齐对账 `catchups`、
  水位 `watermarks`、空窗审计 `gap_audits`、对账附页 `reconcile`。
- 库文件只落在本仓空窗仓区：`data/app.db`（测试落临时库），不引外置库。

## 落库规则（甲）

1. `watermarks`：每源一行水位，随源名录建立而建立（同事务），`watermark_clock` 不得为空。
2. `POST /api/arrivals`：到达落行与水位推进在**同一事务**内提交；
   到达行缺失或时钟对不齐（新水位早于当前水位、或与到达摄入时钟不一致）则整段回滚，
   水位零推进，并向 `gap_audits` 记一条 `空窗审计`。
3. 不提供任何“只抬指针数字”的途径；仅改指针数字判空窗未过，接口拒绝并审计。
4. 双席（调度席/对账席）抢同一源指针：以源为粒度占空窗锁；后交者不推进水位，
   仅在 `gap_audits` 记 `空窗争用`，接口返回 409。
5. `POST /api/catchup/{source}`：该源存在未闭合空窗（水位已越过而无对应到达行）时拦下，
   返回 409 并记 `空窗审计`，不得写“可写”绿灯。
6. `GET /api/reconcile/{source}`：对账附页，返回水位读数与到达详情的对齐结论；
   所有读数字段一律非空（禁止空窗/空值），无数据时给显式空集合与零值，不返回 null。

## 表结构（均为非空列，禁止空窗列）

- `watermarks(source TEXT PRIMARY KEY, watermark_clock TEXT NOT NULL, updated_at TEXT NOT NULL)`
- `gap_audits(id INTEGER PRIMARY KEY AUTOINCREMENT, source TEXT NOT NULL, kind TEXT NOT NULL,
  detail TEXT NOT NULL, created_at TEXT NOT NULL)`，`kind ∈ {空窗审计, 空窗争用, 空窗偏了}`

## 红测顺序（禁止跳过失败测）

1. 先造“指针抬过无到达”夹具，复现空窗误放绿灯，落空窗失败测，误放须红。
2. 再落双席抢针失败测；缺空窗争用留痕则红。
3. 两组红测齐红后，才允许改空窗落库（实现）。
4. 验收全绿；水位读数、到达详情、源名录、任务列表、对账附页均无空值。

## 封档

本卡在首个实现提交前封档，实施当天不得改口；如实现与本卡不符，守卫拦下并在
`gap_audits.kind='空窗偏了'` 留痕。
